1. В чому головна перевага делегування подій порівняно з додаванням обробників addEventListener на кожен окремий елемент списку?
• Відповідь: Головна перевага — це оптимізація використання пам'яті браузера та автоматична робота з динамічними елементами. Замість створення окремого слухача для кожної з дев'яти кнопок (що сильно навантажує систему при великій кількості товарів), ми створюємо лише один слухач на їхній спільний контейнер (.products-grid). Завдяки цьому кліки та події перетягування працюють навіть для тих карток, які завантажуються з інтернету пізніше або генеруються на сторінці динамічно.
2. Як об’єкт події (event) та його властивість event.target допомагають реалізувати делегування?
• Відповідь: Коли користувач клікає по кнопці, подія кліку починає «спливати» (event bubbling) вгору по DOM-дереву від кнопки до її батьківського контейнера, де її й очікує наш слухач. Об'єкт event містить усю інформацію про цей процес, а його властивість event.target чітко вказує на той самий початковий тег, на який фізично натиснули мишкою. Перевірка if (event.target.classList.contains('btn-buy')) допомагає JavaScript точно відфільтрувати потрібні кліки від випадкових натискань на порожні місця чи текст.
3. Що станеться, якщо спробувати знайти кнопку через document.querySelector і повісити на неї подію ДО того, як ця кнопка з’явиться на сторінці (наприклад, під час очікування відповіді від сервера)?
• Відповідь: Метод document.querySelector поверне значення null, оскільки під час надсилання запиту до сервера цієї кнопки ще фізично не існує в DOM-дереві сайту. Спроба викликати метод .addEventListener() на значенні null призведе до виникнення критичної помилки: Uncaught TypeError: Cannot read properties of null (reading 'addEventListener'). В результаті виконання всього JavaScript-файлу повністю зупиниться.
4. Навіщо у події dragover ми обов’язково маємо викликати event.preventDefault()? Що буде без нього?
• Відповідь: За замовчуванням у всіх браузерах увімкнена стандартна поведінка, яка захищає сторінку і блокує можливість «скидання» (drop) будь-яких об'єктів на звичайні HTML-елементи. Метод event.preventDefault() скасовує це дефолтне обмеження браузера. Без цього виклику подія drop просто ніколи не активується, і користувач фізично не зможе відпустити й «кинути» картку товару в зону улюбленого.
5. Яку роль відіграє об’єкт event.dataTransfer у подіях перетягування?
• Відповідь: Об'єкт event.dataTransfer виконує роль спеціального віртуального буфера обміну (контейнера даних), який створений виключно для Drag-and-Drop API. Завдяки йому ми можемо «записати» інформацію (наприклад, унікальний ID товару) в момент початку перетягування картки за допомогою методу .setData(), надійно перенести цей ідентифікатор разом із курсором через весь екран і «прочитати/дістати» його за допомогою методу .getData() в момент відпускання миші над зоною скидання.
